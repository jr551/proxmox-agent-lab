# Code audit — 2026-08-24

Independent audit of `src/proxmox_agent_lab/` and `scripts/` against the repo rules (stdlib only, nothing site-specific, import never fails, tests read fixtures, lease/ownership/audit/expiry/host-shutdown invariants). Findings were produced by three independent reviewers; the critical items were re-verified by hand against the current tree before being recorded here. Line numbers refer to the tree at commit `b7f2de0`.

Status updated 2026-08-25: Critical 1 FIXED, Critical 2 FIXED, Critical 3 RESOLVED (see inline notes). History preserved below.

## Critical

1. **Command injection into the share worker via label — FIXED** — `share.py:363-365`, `share.py:401-402`. The label is embedded in a remote `bash -c` string guarded only by `json.dumps()`. Bash double quotes do not stop `$()` or backticks, so a label of `` x`reboot` `` executes as root on the share worker — which holds a Proxmox API token at `/etc/pxl-share/config.json`. Fix: pass arguments as argv to the worker helper (`["pxl-share", "add", "--label", label]`), never string assembly. **Update 2026-08-25:** Verified fixed — `share.py:373-375` now builds `command = ["pxl-share", "add", "--vmid", ..., "--label", label]` and executes via argv helper `_run(lab, api, command)` with no shell interpolation.

2. **WebSocket TLS verification hard-disabled — FIXED** — `ws.py:48-50`. `check_hostname=False`, `verify_mode=CERT_NONE` with no config hook. Issue #72 was fixed for REST and for the share server, but every VNC/terminal websocket still ignores `[proxmox] verify_tls` — even when it is `true`. The channel carries VNC auth responses and serial-console passwords. Fix: thread the config flag into `_open_websocket`. **Update 2026-08-25:** Verified fixed — `ws.py:48` now accepts `verify_tls: bool = True` and gates `check_hostname`/`CERT_NONE` on it; `console.py:109` threads `lab.VERIFY_TLS` (from `[proxmox] verify_tls`) into `WebSocket`, and `cli.py:61` exposes `VERIFY_TLS = bool(CONFIG.proxmox.verify_tls)`.

3. **mcp-activity-proxy crashes at startup — RESOLVED (file deleted)** — `scripts/mcp-activity-proxy.py:12` imports `proxmox_lab`, deleted in commit `03db912`; `cli.py:3074-3079` builds a shim module (`ModuleType("proxmox_lab")` inside package `proxmox_agent_lab`) but originally never registered it in `sys.modules`. Reproduced: the proxy exited with `ModuleNotFoundError`, silently disabling MCP idle recording and therefore the MCP-idle host-shutdown enforcement described in `docs/safety-policy.md`. **Update 2026-08-25:** RESOLVED — file deleted, only check-secrets/check-public/check-release remain; residual cli.py shim at 3074-3079 kept for compat (now registers `proxmox_lab` in `sys.modules` for path-loaded use). `scripts/` now contains only `check-public.py`, `check-release.py`, `check-secrets.py`, `install-watchdog`, and `proxmox-lab`; CodeModules verification confirms no remaining `import proxmox_lab` reference in the tree (only `__pycache__` artifact).
